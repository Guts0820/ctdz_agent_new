# 当前完整工作流与项目完成度（2026-08-23）

> 本文以当前代码、已验证接口和已经确定的产品决策为准。  
> 状态标记：✅ 已完成并有代码/测试；🟡 部分完成或存在已知缺口；⏳ 已规划但尚未实现；🚫 已明确取消。  
> 本项目当前重点是“教师限定题目范围、统一题库复用、一次标准解题、学生安全练习和订正闭环”。

## 一、与原始设计相比的总体改进

原始工作流将学生拍照后的题目直接带入“知识图谱检索 -> 错因分析 -> 教学生成 -> 复习计划”，并把教师端、管理员端主要停留在接口规划层面。当前版本已经完成了以下结构性改进：

1. 从“规则/模拟链路”推进到真实的 OCR -> 网关 -> 分析 -> 状态 -> 复习服务链路。
2. 题目识别和标准答案判题已经拆开，图谱服务不可用时具备降级和本地判题能力。
3. 错题可以进入统一错题本，并支持真实订正、订正记录和掌握度刷新。
4. 掌握度和优先级已经从原来简单的连对/连错设想，推进为可计算、可持久化的 Mastery + Priority 模型。
5. Review 2.0 已有计划、Session、答题、暂停/恢复和订正接口，复习计划不再是原文中的固定 Day1/Day3/Day7 方案。
6. 教师端已经有班级数据、学生详情、错题分析和作业批次入口；作业批次默认锁定并支持一键/精细放行的后端基础。
7. Neo4j 启动、知识图谱检索失败降级、OCR 置信度策略和后端服务编排已经补齐。
8. 原设计中的“疑似抄袭判断”和“苏格拉底式多轮引导追问”已经明确不做，本版不再将它们列为待开发功能。

仍未完成的关键升级是：统一 canonical 题库和题目指纹去重、教师题目录入后标准解题只调用一次、学生只能匹配教师批次题目，以及未放行答案的后端零泄露。

## 三、学生端当前工作流

### 3.1 拍照上传 -> OCR -> 判题

```text
学生选择学生角色
  -> 上传/拍摄作答图片
  -> OCR 提取题干与学生最终作答
  -> 校验结构化结果、题干、作答和置信度
  -> 匹配题库/知识图谱标准题目
  -> 使用标准答案判题
  -> 记录 answer_history
```

当前已完成：

- 图片上传和 OCR 结构化结果校验。
- 学生 OCR 置信度阈值与教师标准答案阈值分离。
- 图谱检索失败时不再直接返回 503；简单算式可以走安全本地判题。
- 识别成功的正确题更新学习状态；错误题进入错题本/错题订正链路。
- 未结构化、题干缺失、作答缺失和低置信度错误已经拆分，不再统一误报“图片模糊”。

当前缺口：

- 学生未知题仍可能走待审核题写入逻辑；按照最终决策，应改为直接返回“题目不在题库中”，不得进入正式统一题库。
- 尚未强制要求学生请求携带当前班级/作业批次上下文，题目匹配范围还没有完全收紧到教师批次。
- 尚未完成统一题目规范化指纹，无法严格保证不同 OCR 表达只对应一个 canonical question。

最终 LLM 调用策略：

- 学生端保留个性化错因分析；学生答错时可以调用一次错因 LLM，生成该学生本次作答的错误标签和针对性反馈。
- 学生端不再调用“标准解题 LLM”；标准答案、标准步骤和通用解析从统一题库读取。
- 教师创建作业时应向学生下发 `batch_id + question_id`，优先按题目 ID 判定，减少学生端候选题 LLM 重排。
- 学生答对时不调用个性化错因 LLM；学生答错时才调用个性化错因 LLM。

### 3.2 判题后反馈和错题本

当前已完成：

- 正确作答记录历史并刷新掌握度。
- 错误作答可以创建 `mistake_case`，并在错题本中展示。
- 错题订正支持重新提交、订正次数、订正是否正确、订正时间和掌握度更新。
- 错题订正链路已通过后端测试，学生可以从错题本进入订正。

明确取消：

- 🚫 疑似抄袭判断：不做，不作为主链路分支。
- 🚫 苏格拉底式多轮引导追问：不做，不再建设多轮追问接口。

### 3.3 首页今日推荐和复习计划

当前已完成：

- 首页有“今日推荐/建议学习”入口。
- 复习计划支持按题量生成，默认每日题量上限为 10，道理上限制在 30 以内。
- Review 2.0 具备创建计划、开始 Session、查看当前题、提交答案、暂停/恢复和订正基础链路。
- 复习优先级由真实答题证据、掌握度和 Priority 计算驱动；Neo4j 无题时可以读取 SQLite 题库。

当前缺口：

- 复习计划尚未完全限制为“当前学生所属班级已分配批次”的题目集合。
- 复习开始接口目前仍会把 `answer`、`answer_steps` 置于学生题目对象中，存在接口/浏览器调试泄露风险。
- 前端答错反馈仍有从当前题目对象读取答案的逻辑，必须删除，改为只消费后端显式授权字段。

### 4.2 教师录入标准题目和统一题库

目标工作流：

```text
教师拍照/上传题目
  -> OCR 只识别题干
  -> 规范化题干并计算 question_fingerprint
  -> 指纹命中 ready 题目：直接复用
  -> 未命中：创建唯一题目并调用一次 LLM 生成答案/步骤/解析
  -> solution_status=ready 后，题目可加入教师作业批次
```

当前状态：⏳ 未完成。

尚未实现的核心能力：

- `normalized_text`、`question_fingerprint` 和唯一索引。
- `solution_status=pending/processing/ready/failed` 状态机。
- LLM 标准解题任务的幂等锁和调用审计。
- 教师题目录入成功后才允许布置；`pending` 题目不得进入学生作业。
- 学生上传未知题直接返回“题目不在题库中”，不创建正式题目。

成本目标：教师端对每个唯一新题最多进行一次标准解题 LLM 调用；学生端每次上传仍需识图，但不重复生成标准答案，只有答错时保留一次个性化错因分析调用。

- 一键放行和精细放行接口已存在。
- 教师前端已有创建批次、勾选题目、一键放行和精细放行按钮。

当前缺口：

## 六、答案安全与放行规则（当前要求）

最终产品规则如下：

1. 学生未知题不能进入正式统一题库，直接显示“题目不在题库中”。
2. 同一道题可以属于多个批次，答案权限按学生正在练习的当前批次判断；不同批次互不影响。
3. 教师录入题目必须先达到 `ready`，才允许加入正式作业批次；`pending` 题目不能布置。
4. 批次创建后默认 `locked`；教师一键放行或精细放行后，学生才可以获得该批次对应题目的标准答案、步骤和完整解析。
5. 放行前即使学生答对，也只返回“回答正确”，不返回标准答案、标准步骤或完整解析。
6. 后端响应层必须字段级脱敏。锁定状态下不能返回：`answer`、`answer_steps`、`standard_answer`、`standard_solve_steps`、`standard_explanation`、完整 `explanation`、`common_errors`、`teaching_tips`。
7. 放行查询失败按未放行处理（fail-closed），不能因为数据库异常而泄露答案。

当前实现状态：🟡 规则已经确定，部分后端判断已存在，但完整零泄露尚未完成。

## 九、验收标准

- 教师创建或录入同一题多次，统一题库只有一个 canonical `question_id`。
- 教师端同一题标准解题 LLM 调用最多一次，后续学生直接复用已保存结果；学生端答错时仍可进行一次个性化错因分析。
- 学生上传不在教师批次内或不在统一题库的题目，直接得到“题目不在题库中”。
- 教师刷新页面后仍能看到真实批次、题目和放行状态。
- 锁定批次下直接调用 API、查看 Network、浏览器对象和缓存，都找不到答案、步骤和完整解析。
- 放行指定批次/指定题目后，仅对应学生和批次获得允许字段。
- Review 2.0 的创建、开始、恢复、答题、错误、订正和完成状态全部可追踪。
- 疑似抄袭和苏格拉底追问不会出现在验收范围内。
- 成长报告能够返回真实五维能力分数、薄弱知识点、近期进步和学习路径；无答题数据时返回明确的空状态。
- 能力雷达图五个维度由后端统一计算，学习韧性不得使用固定默认值，并能在学生答题/订正后更新。
- 后端、前端和端到端测试通过，变更推送至 `origin/main`。

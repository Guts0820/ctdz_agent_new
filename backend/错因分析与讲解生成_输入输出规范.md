# 错因分析 Agent + Teaching Service 输入输出规范

## 一、Error Analysis Agent（端口8082）

### 接口一：主链路错因分析
`POST /internal/api/v1/error-analysis/analyze`

**输入（ErrorAnalysisRequest）**
```json
{
    "student_id": "S-0001",
    "question_id": "Q-0001",
    "original_question": "题目文本",
    "student_write": "学生作答",
    "judge_result": "wrong",
    "core_error_type": "计算失误",
    "step_feedback": "批改反馈文字",
    "error_step_list": ["错误步骤描述"],
    "miss_step_list": ["缺失步骤描述"],
    "confidence": 0.85
}
```

**输出（ErrorAnalysisResponse）**
```json
{
    "error_tags": [
        {
            "error_id": "C-001",
            "level1": "计算",
            "level2": "口算与基本运算",
            "level3": "进位加法中十位漏加进位1",
            "confidence": 0.92
        }
    ],
    "knowledge_id": "K035",
    "knowledge_scope": "100以内进位加法",
    "reasoning_content": "推理过程文字",
    "total_confidence": 0.92
}
```

**注意**：`total_confidence < 0.7`时，接口会直接返回400错误"Low confidence, requires human review"。

### 接口二：轻量模式（服务晓琳前端，信息量较少的场景）
`POST /internal/api/v1/error-analysis/analyze-light`

**输入**
```json
{
    "student_id": "U-1",
    "original_question": "题目文本",
    "standard_solve_steps": "标准解题步骤",
    "correct_answer": "正确答案",
    "student_write": "学生最终答案",
    "knowledge_id": "K004"
}
```

**输出**
```json
{
    "error_type": "C-004",
    "error_type_label": "20以内加减法不熟练",
    "error_detail": "推理说明",
    "related_knowledge": ["1-5的加减法"],
    "confidence": 0.6,
    "all_error_tags": [...],
    "knowledge_id": "K004",
    "source": "light_analysis",
    "note": "本接口为轻量分析模式，仅基于最终答案推断，置信度相对保守"
}
```

**注意**：置信度上限硬约束为0.6，且这个接口不写入`mistake_case`表。

## 二、Teaching Service（端口8084）

`POST /internal/api/v1/teaching/generate`

**输入（TeachingGenerateRequest）**
```json
{
    "error_tags": [
        {"error_id": "C-001", "level1": "计算", "level2": "口算与基本运算", "level3": "进位加法中十位漏加进位1"}
    ],
    "knowledge_scope": "100以内进位加法",
    "knowledge_id": "K035",
    "master_level": 0.3,
    "original_question": "题目文本",
    "student_write": "学生作答",
    "difficulty": "medium",
    "grade": "三年级"
}
```

**输出（TeachingGenerateResponse）**
```json
{
    "explanation": "针对具体错因的讲解文字（目前是完整一段，包含正确答案）",
    "hints": ["启发式提示1", "启发式提示2", "启发式提示3"],
    "practice_list": [
        {
            "question_id": "Q-XXXX",
            "question_description": "题目文本",
            "difficulty": "medium",
            "answer": "答案",
            "solution": ""
        }
    ],
    "reasoning_content": "生成依据说明",
    "teaching_mode": "BASIC / STANDARD / ADVANCED"
}
```

**教学深度档位判断规则**（不涉及LLM，纯数值判断）：
- `master_level < 0.4` → BASIC（详细分步讲解）
- `0.4 <= master_level <= 0.8` → STANDARD（简洁讲解）
- `master_level > 0.8` → ADVANCED（简短巩固提醒，不返回`practice_list`）

**⚠️ 与"答案解锁"功能相关的关键点**：目前`explanation`字段是完整一段文字，正确答案和讲解过程混在一起，没有拆分。如果要做"老师放行前只给过程、不给答案"这个功能，需要先改造这个字段的输出结构（拆成`guided_explanation`和`final_answer_explanation`两部分），这是新功能需要新增的改动，不是现有接口就能支持的。

## 三、两者串联关系

```
学生提交作业
    ↓
Analysis Service 判题（is wrong）
    ↓
Error Analysis Agent（用主链路接口，需要完整的批改上下文）
    → 输出 error_tags + knowledge_id
    ↓
Knowledge Service 查知识点详情
    ↓
Teaching Service（用 error_tags + knowledge_id + master_level）
    → 输出 explanation + hints + practice_list
    ↓
State Service 更新掌握度、生成复习计划
```

轻量模式（`analyze-light`）是给晓琳前端单独用的旁路，**不经过这条主链路**，也不会触发后续的Teaching Service调用——晓琳那边目前只要错因分析这一层，讲解生成暂时不在这次对接范围内。

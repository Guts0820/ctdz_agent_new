## 二、学生端工作流

### 2.1 主流程：提交错题 → 分析 → 反馈

```
①学生拍照/输入题目和答案
        │
        ▼
②OCR识别（分离题目文本、学生作答）  【❓待定：如何处理图文结合题、手写体识别】
        │
        ▼
③判断对错
        │
   ┌────┴────┐
   ▼         ▼
 答对      答错/疑似抄袭
   │         │
   │         ▼
   │    是否疑似抄袭？
   │    ┌────┴────┐
   │    是         否
   │    │          │
   │    ▼          ▼
   │  苏格拉底式  错因分析Agent
   │  引导追问    （三级错因标签 + 关联知识点）
   │  【暂缓开发，  │
   │   已确定方向，  ▼
   │   多轮对话   知识图谱检索
   │   接口未实现】  （知识点讲解、常见错误、教学提示）
   │              │
   │              ▼
   │           生成教学内容
   │           （讲解 / 提示 / 变式题）
   │           三档难度：BASIC / STANDARD / ADVANCED
   │              │
   ▼              ▼
更新掌握度（Mastery+Priority模型）
   │
   ▼
生成/更新复习计划
```

### 2.2 订正流程 ❓【待定，明日组会讨论】

- 学生对错题重新作答后，走的是否是同一套流程（相当于步骤①②③重新走一遍）？
- 系统是否需要专门区分"这是第一次做"还是"这是订正"？（数据库 `answer_history.submit_type` 字段已预留"首次错题/错题订正"这两个值，但目前代码逻辑还没真正利用这个区分）
- 订正对了 → 推变式题；订正错了 → 回退到更基础的知识点讲解 + 简单题（这个走向是最早讨论时定的方向，具体交互细节待订正流程本身确定后再细化）

### 2.3 复习计划

- ✅ 掌握度模型：采用 Mastery + Priority 双模型（详见第五节）
- ⏳ 每日复习题量上限：需要控制，避免"越攒越多、用户失去兴趣"，具体每天几道题/多少分钟，由负责这块的同学先定一个初始值（比如10道/20分钟），后续可调整
- ⏳ 复习题型与错因的对应关系：不同错因类型是否应该推不同题型（比如"概念混淆"类错因应该多推概念辨析题，"计算失误"类应该多推同类计算题），具体映射规则待设计

### 2.4 成长报告（面向家长）

- ✅ 已确定要做，导师明确要求
- ❓【待定】具体维度：目前只有"数学思维、数学逻辑、书写规范"这类初步设想，最终维度需要组内/导师进一步商定
- ⏳ 展示形式：雷达图可视化，对比"使用前 vs 使用后"的变化
- ❓【待定】这个功能挂在"学生端"里给家长查看，还是需要单独做一个"家长端"入口？

## 五、贯穿全流程的核心引擎：掌握度 + 优先级模型

这是支撑"学生端复习计划"和"教师端易错点分析"的底层计算逻辑，独立于三端之外，是整个系统的"大脑"。

### 5.1 掌握度模型（回答"学生会不会"）

对每个知识点，计算四个维度并加权：

```
正确能力 Accuracy（历史正确率 + 最近加权正确率）
稳定性 Consistency（结果是否稳定，波动率 + 连续对错修正）
记忆保持度 Retention（距离最近一次正确的天数，按记忆衰减曲线计算）
错误控制 Error Control（错因严重程度的反向指标）
        │
        ▼
Mastery = 0.4×Accuracy + 0.25×Consistency + 0.2×Retention + 0.15×Error_Control
        │
        ▼
按数据量做可信度修正（做题次数少时，结果向50分收缩，避免"一次蒙对就100分"）
```

### 5.2 优先级模型（回答"现在该优先复习哪个"）

```
能力缺口 Gap（100 - 技能掌握度）
错因严重程度 Error Severity（概念性错误 > 粗心错误）
遗忘风险 Forgetting Risk（100 - 保持度，距离上次正确越久风险越高）
知识点重要程度 Importance（教材核心程度，❓需要人工标注，标注人选待定）
学习趋势 Trend（近期是进步还是退步）
        │
        ▼
Priority = 0.35×Gap + 0.25×Error_Severity + 0.20×Forgetting_Risk + 0.10×Importance + 0.10×Trend
        │
        ▼
每日按 Priority 从高到低排序，取前 N 个（N = 每日题量上限），凑够即停止推送
```

> 注：以上系数（0.4、0.25、3、8、0.85 等）均为初始经验值，不是训练得出的最终参数，上线后需要根据实际使用效果校准。

| 数据项 | 用途 | 谁来标注 |
|---|---|---|
| 错因严重程度（11类，0.15-1.00） | 计算 Error Severity | 已有初版建议表，需人工/组内确认 |
